## 1. Zweck

OSAI.FunktionsBefehle beschreibt Befehle,
die später als Eingaben im OSAI-Interface nutzbar werden können.

Das Modul ist noch nicht endgültig versiegelt.

Es dient als Bedienungsanleitung für:

- Funktionsrollen
- Interface-Kommandos
- semantische Zustände
- Archivbewegung
- LINK-Verhalten
- CORE-nahe Arbeit
- zukünftige OSAI-Interaktion


---

## 2. Grundregel

Fae bleibt der CORE-Name.

Das kleine f vor einem Begriff bedeutet:

Funktionsmodus.

Beispiel:

Fae
= CORE-Name

fFae
= Fae im Funktionsmodus

fLink
= Verbindung herstellen

fTrace
= Spur sichern

fMirror
= Gedanken spiegeln

fSeal
= Zustand versiegeln


---

## 3. Befehlsraum

Es gibt zwei empfohlene Schreibweisen:

o.fb
= lesbare Modulform

/ofb
= Interface- oder Kommandoform

Beispiele:

/ofb fIndex
/ofb fLink EIC.1998 ARTCORE
/ofb fTrace YouTube-Quelle ARC
/ofb fMirror Text
/ofb fSeal intrOfore

## 6. Empfohlene Befehlssyntax

Grundform:

/ofb [funktion] [ziel] [optionaler kontext]

Beispiele:

/ofb fIndex ARTCORE
= ARTCORE indexieren

/ofb fTrace EIC.1998 YouTube
= EIC.1998 mit YouTube-Quelle als Spur sichern

/ofb fLink M0541K.de GitHub
= M0541K.de und GitHub sauber verbinden

/ofb fSplit lokal online
= lokale und Online-Struktur trennen

/ofb fRoute Kupferplatte2006 ARTCORE
= Kupferplatte 2006 in ARTCORE einordnen

/ofb fSeal OSAI.VERSION.SYSTEM
= Versionierungsregel versiegeln, falls bestätigt

/ofb fPatch index.html
= gezielten Fix an index.html vorbereiten

/ofb fExport pdf OSAI.FunktionsBefehle
= PDF aus diesem Modul erzeugen

## 7. Statuswerte

Jede Funktion kann einen Status erzeugen.

OPEN
= gefunden, aber nicht entschieden

DRAFT
= entworfen, aber nicht final

LINKED
= verbunden

CHECKED
= geprüft

FIXED
= repariert

ARC
= archiviert

ARTCORE
= als Werk relevant

CORE-CANDIDATE
= möglicherweise kernrelevant

RELEASE-CANDIDATE
= publikationsfähig, aber noch nicht veröffentlicht

SEALED
= bewusst versiegelt

PUBLIC
= öffentlich nutzbar

PRIVATE
= nur lokal / intern


---

## 8. Sicherheitsregel

Ein Funktionsbefehl darf den CORE nicht automatisch überschreiben.

CORE-Änderungen brauchen immer einen bewussten Schritt:

/ofb fSeal [ziel]

oder

/ofb fCore [ziel] CHECK

Erst danach kann entschieden werden,
ob etwas wirklich in den CORE wandert.


---

## 9. Lokal / Online Regel

Für Dateien und Webstruktur gilt:

/ofb fSplit lokal online
= trennt lokale Archive von veröffentlichten Dateien

/ofb fSync
= prüft, was lokal und online auseinanderläuft

/ofb fRoute
= entscheidet, wo ein Element hingehört

Grundsatz:

0S41
= lokales Anfangsarchiv / frozen archive

OSAI_v1alpha
= aktive Arbeitsversion

GitHub Pages
= öffentliche Webstruktur

M0541K.de
= öffentlicher Besucheranker

OSAIarc
= Zeitspur / Archivbewegung
